# Кандзи дня

Спокойное мобильное веб-приложение для изучения одного кандзи в день —
для полных новичков, ещё не знающих кану. Интерфейс на русском,
японский показывается с каной и ромадзи. Без очков, стриков и наград.

## Структура

```
everyday-kanji/
├── backend/            FastAPI + SQLAlchemy 2 (async) + Alembic
├── frontend/           React + TypeScript + Tailwind v4 + shadcn/ui на Vite
├── nginx/              обратный прокси, единственная точка входа
├── docker-compose.yml
├── docker-compose.dev.yml
└── .env.example
```

Наружу публикуется **только** nginx, и строго на `127.0.0.1`. Бэкенд,
фронтенд, PostgreSQL и Redis доступны лишь внутри сети Compose.

Фронтенд и API живут на одном домене не для красоты: идентификация
держится на куке `device_id`. Раздавай мы статику с другого источника,
кука перестала бы ходить и сервер заводил бы новое устройство на каждый
запрос.

## Запуск

```bash
cp .env.example .env          # и подставить свои значения
make up
make migrate
make seed
```

`make` без аргументов покажет список команд. Длинные строки `docker compose`
никуда не делись — Makefile их только сокращает, и любую можно набрать руками.

Приложение — на `http://127.0.0.1:8082` (порт меняется через `APP_PORT`).
Документация API вне production — на `/api/docs`.

```bash
curl http://127.0.0.1:8082/api/health
```

## Разработка

Фронтенд удобнее гонять дев-сервером Vite: он проксирует `/api` на
`127.0.0.1:8082`, то есть на тот же nginx, поэтому кука ведёт себя как в
продакшене.

```bash
cd frontend
npm install
npm run dev     # :5173
npm run build
```

Для бэкенда есть отдельный compose-файл с монтированием исходников и
авто-перезагрузкой. Он назван **не** `docker-compose.override.yml`
намеренно: override подхватывался бы автоматически, и его легко
применить на сервере по невнимательности.

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d
```

### Миграции

Без монтирования исходников Alembic создаст файл внутри контейнера, и он
исчезнет вместе с ним при `--rm`, поэтому новые миграции генерируются
только так:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml run --rm backend \
  alembic revision --autogenerate -m "описание"
```

Применяются обычной командой, но **образ нужно пересобрать** — иначе
файл миграции в него не попадёт:

```bash
docker compose build backend
docker compose run --rm backend alembic upgrade head
```

Для `seed` пересборка **не** нужна: каталог `backend/data` монтируется в
контейнер, поэтому справочник читается с диска, а не из образа.

Миграции намеренно не запускаются при старте приложения: при нескольких
воркерах это даёт гонку.

## Сеть и безопасность

- Порт публикует только nginx и только на `127.0.0.1`. Явный адрес
  обязателен: без него Docker пишет правила прямо в iptables в обход
  ufw, и порт оказывается открыт всему интернету.
- nginx **перезаписывает** `X-Real-IP` значением `$remote_addr`. На нём
  держится лимитер, а `X-Forwarded-For` в левой части контролируется
  клиентом. Проверено: запрос с подделанным `X-Real-IP` не создаёт
  отдельный счётчик и лимит обойти не позволяет.
- `proxy_pass` задан через переменную вместе с `resolver 127.0.0.11`.
  Иначе nginx резолвит имя сервиса один раз при старте, а после
  `up -d --build` контейнеры получают новые IP — и прокси отдаёт 502 до
  ручного рестарта.
- uvicorn запускается с `--proxy-headers --forwarded-allow-ips="*"`. Это
  безопасно ровно потому, что контейнер недоступен извне.

## Redis

Только кэш и счётчики лимитера, поэтому персистентность отключена
(`--save "" --appendonly no`) и тома нет. Ограничение памяти — 256 МБ с
политикой `allkeys-lru`.

Побочный эффект политики: под давлением памяти может быть вытеснен
счётчик лимитера, и лимит на время ослабнет. При наших объёмах это
маловероятно, но это осознанный компромисс.

## Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | Живость процесса, без обращения к зависимостям |
| GET | `/api/kanji` | Справочник, пагинация и фильтр по JLPT |
| GET | `/api/kanji/{id}` | Один иероглиф |
| GET | `/api/trail` | Главный экран: лента изученных, знак дня |
| GET | `/api/lesson/today` | Повторения на сегодня плюс новый знак дня |
| GET | `/api/reviews/due` | Карточки, готовые к повторению |
| POST | `/api/reviews/{kanji_id}` | Ответ на карточку, пересчёт SRS |
| GET | `/api/stats` | Краткая статистика устройства |
| GET | `/api/sources` | Источники данных, лицензии, внесённые изменения |

Клиент шлёт заголовок `X-Timezone` с таймзоной IANA — от неё зависит
граница суток для дневных счётчиков. Фронтенд делает это сам в
`frontend/src/lib/api.ts`.

Номер знака («день 9») означает порядок изучения **этим устройством**, а
не общий календарный день курса: с появлением SRS каждый идёт своим
темпом.

## Алгоритм повторений

SM-2 с тремя оценками вместо канонических шести: `again` / `good` /
`easy` (внутренние q = 2 / 4 / 5). Шесть градаций — избыточный выбор для
новичка и противоречат спокойному тону приложения.

Полноценных learning steps нет: при ответе «не помню» карточка
возвращается через 10 минут. Из-за этого `interval_days` и
`next_review_at` могут расходиться — первое хранит интервал по SM-2 в
днях, второе фактический момент показа.

## Справочник кандзи

В базе все **2136** иероглифов дзёё, но в уроки попадают только записи с
выверенным вручную русским значением (`is_published`). Сейчас таких
**81** — весь уровень JLPT N5 плюс один знак сверх него, то есть около
трёх месяцев ежедневных уроков.

Открытого источника «кандзи → русское значение» не существует, поэтому
смысл проходит через две ступени: модель переводит готовые английские
глоссы KANJIDIC2 в черновик, человек подтверждает перевод. Публикует
только вторая ступень — машинный текст хранится отдельным полем и наружу
не отдаётся.

Пересборка справочника — собрать и сразу залить:

```bash
make content
```

Это пара `make dataset` + `make seed`. Разделять их обычно незачем: собранный,
но не залитый справочник до приложения не доезжает, и забыть второй шаг легко.

**Подробности — в [docs/kanji-pipeline.md](docs/kanji-pipeline.md):**
источники и их покрытие, перевод и вычитка значений, система записи
ромадзи, как добавить новый знак в уроки, известные пробелы.

## Тесты

Автотестов сейчас нет. Единственный существовавший проверял расчёт
границы суток на фронтенде, а эта логика переехала на сервер. Самое
ценное к покрытию — SM-2 и вычисление локальных суток в
`backend/app/services/`.
